NVDLA is a modular deep learning inference accelerator, and this module handles the memory interface for read operations.

This module is a converter that takes read commands from an internal splitter and transforms them into AXI4 read address channel transactions. The module ports are already defined for you.

Important: Study the surrounding modules in sources/vmod/nvdla/nocif/ to understand how this converter fits into the system. What the module needs to do:

The incoming command packet contains everything needed to build an AXI transaction: a client ID, a memory address, a size field, and several flags. Study how the upstream module packs its output to understand the exact bit positions and their meanings.

For the AXI side, generate standard read address channel signals. The address must be aligned appropriately for AXI transactions. The burst length calculation depends on the size field, but there are edge cases involving the transfer flags and other fields that affect this calculation.

The module writes context information to a queue for downstream processing. This context packet must carry enough information for downstream logic to correctly handle the returning data, including burst length, relevant flags, and drop flags. The drop flags indicate when parts of AXI beats should be discarded due to alignment considerations. Study how downstream modules consume this context to understand the expected format.

Flow control requires coordination between three conditions: the AXI output must be ready, the context queue must be able to accept writes, and there must be room for outstanding transactions. The outstanding counter tracks beats in flight and must be managed correctly based on transaction issuance and completion feedback.

Include a pipeline register stage on the AXI output path for timing closure.

The context queue thread ID output should pass through the client ID from the incoming command.

The AXI ID and length outputs are wider than the internal values. Zero-extend appropriately.
