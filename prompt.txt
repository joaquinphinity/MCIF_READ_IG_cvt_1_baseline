What the module needs to do:

The incoming 75-bit command packet contains everything needed to build an AXI transaction: a client ID, a memory address, a size field, and several flags. The exact bit positions and their meanings can be found by studying how the upstream splitter packs its output. Pay close attention to all the fields and flags, as each one affects the behavior of this converter.

For the AXI side, generate standard read address channel signals. The address must be aligned appropriately for AXI transactions. The burst length calculation depends on the size field, but there are edge cases involving the transfer flags and other fields that affect this calculation. Analyze the data path architecture to understand when additional beats might be needed.

The module writes context information to a queue for downstream processing. This 7-bit context packet must carry enough information for downstream logic to correctly handle the returning data. This includes the burst length, relevant flags from the original command, and two drop flags. The drop flags indicate when parts of AXI beats should be discarded. To understand when dropping is necessary, think about how NVDLA's internal data width relates to AXI beat sizes, and how address alignment affects which portions of a beat contain useful data versus padding. The logic for these flags can be derived from understanding the memory architecture.

Flow control requires coordination between three conditions: the AXI output must be ready, the context queue must be able to accept writes, and there must be room for outstanding transactions. The outstanding counter tracks beats in flight and must be managed correctly based on transaction issuance and completion feedback.

Include a pipeline register stage on the AXI output path for timing closure. You can find examples of such pipeline stages in the shared library.

Context queue packet format (7 bits):
The context queue data packs fields starting from the least significant bit: burst length in bits [1:0], then swizzle flag, odd flag, last transfer flag, first-beat-drop flag, and last-beat-drop flag in the upper bits.

Thread ID:
The context queue thread ID output should pass through the client ID from the incoming command.

Outstanding counter behavior:
When a transaction is issued, the counter increases by the number of beats in that transaction. The decrement signal from completions should be registered before being used to update the counter.

AXI output widths:
The AXI ID and length outputs are wider than the internal values. Zero-extend appropriately.
